プロジェクト規約の `archive/plan/` にも同じ計画を保存する。

## 方針

タスク 2 の確認済み `archive/quality/placement-constraints/after.pptx` を最終版として固定する。
元 PDF、P0 前の `before.pptx`、最終版を SHA-256 と生成コミットで同定する。
既存 PPTX の再保存や PowerPoint の画像書き出しは行わない。
LibreOffice で背景と文字を含む PDF を取得し、Poppler で PNG に描画する。
実資料は `archive/quality/full-page-review/` に保持し、公開する例には合成画像と文字だけを使う。

元 PDF は 1376 × 768 pt、PPTX は 960 × 540 pt。
元 PDF の 72 DPI の 1376 × 768 px を比較座標とし、PPTX の完成表示をこの寸法へ明示的に拡縮する。
切り抜きと余白追加は行わず、縦横の倍率を記録する。
優先領域は同じ比較座標で切り出し、原寸と最近傍補間による 200% を保存する。
LibreOffice での日本語表示の制約は資料へ明記し、PowerPoint の完成表示と呼ばない。

## 実装

1. `xtask quality-eval` に名前、分類、ページ、座標系、しきい値を持つ JSON 設定を追加する。
   背景画素差、色の混入、保護画素、マスク重なり、OOXML 文字と書式、PowerPoint の保存済み実描画範囲を個別評価する。
   欠損、空の評価対象、座標誤りを合格にせず、未測定を明示し、必須項目の失敗時は非ゼロで終了する。
2. 小さな局所破損、保護画素 1 個の変更、マスク重なり、大小文字と部分強調の変化、描画越境と欠測を先にテストして Red を確認する。
3. 入力のハッシュ照合、描画、14 枚の三者比較、一覧、優先領域、共通評価を再実行する Python 補助ツールを追加する。
   Python の依存は PEP 723 と `uv run` を使い、グローバルへインストールしない。
4. 検証可能な合成例と使用方法を `macos-app/docs/quality-review/` に保存する。
5. 実資料の比較画像を目視確認し、評価結果と既知の制約、再生成コマンドを記録する。

## 検証予定

評価器は `cargo test --locked -p xtask`、整形、Clippy で確認する。
Python 補助ツールは構文検査と合成入力・実資料の再実行で確認する。
PPTX 生成処理は変更しないため、PowerPoint 互換性と既存 fixture の再記録は不要。
保存済み PowerPoint 計測の対象 SHA と件数を照合し、今回の再計測と誤表記しない。
性能比較 (タスク 4)、親計画全体の整合 (タスク 5)、表示言語の検討 (タスク 7) は別タスクとして維持する。
