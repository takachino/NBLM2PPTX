# 文字消去の滲みの根本対策

作成日: 2026-11-03
対象 Issue: [#10](https://github.com/takachino/NBLM2PPTX/issues/10)
基準: `8465903` (`feat/multilingual-ja`)
状態: 計画。実装は未着手。
同じ計画をプロジェクト規約の `archive/plan/` にも保存する。

## 目的と範囲

表のセルや格子柄の上にあった文字を消すときに残る滲みを、消去処理の入力を直して解消する。
滲みは、罫線の欠け、白い帯、暗いもや、元にない文字の描き足しとして現れる。
LaMa のモデル (`lama_fp32.onnx`) と取得方法は変更しない。

対象は標準版の文字消去で、`--erase lama` と、LaMa がない場合の `stroke` を含む。
`inpaint` と `fill` の消去方式、透かし除去、物体抽出の判定は変更しない。
ただし、物体抽出が参照する消去済みマスクは新しいマスクに合わせる。
図の一部の数字を OCR が文字と判定する問題は対象外とする。
GUI と CLI は同じ処理を使うため、両方に反映される。

## 調査で分かったこと

詳細は Issue #10 にまとめた。
実資料、比較画像、試作スクリプトは、ローカルの `archive/quality/erasure-smudge-root-cause/` に保存した。

1. OCR の行枠がセルの罫線に接し、文字と同じ色の罫線が筆画として消去マスクに入る。
2. 元画像の白文字の暗い縁がマスクから漏れ、局所補間がその画素を起点に塗り広げる。
3. LaMa を行ごとに呼ぶため、まだ消していない隣の行を手本にして文字列を描き足す。
4. 平坦判定が色差 60 以内を背景とみなすため、淡い格子柄を単色で塗りつぶす。
5. `small_ui_text` の保護範囲が編集対象の見出しにかかり、補間後に元の画素を戻す処理で見出しの下半分が背景に残る。

Python の試作では、3 つの変更を組み合わせて、検証した 5 ページの滲みがほぼ解消した。
罫線を除外すること、暗い縁と薄い影をマスクに含めること、全行を一度に LaMa で補間することである。
同じマスクでも、行ごとの LaMa では文字が描き足された。
背景色からの補間は、周囲が単色の場合だけ最も平坦だった。
一方で、隣の図形の縁を削るページや、格子柄を消すページがあった。

## 方針

- 消去を 3 段階に分ける。全行の消去マスクを作り、連結成分ごとに補間方法を決め、まとめて補間する。
- 罫線と枠線は「壁」として扱う。消去マスクに入れず、補間の境界値にも使わない。
- LaMa は、ページごとに合成したマスクで 1 回だけ実行する。行ごとの呼び出しは廃止する。
- 背景色からの補間は、周囲がすべて背景色に近い連結成分に限る。
- 編集対象の行の文字枠の内側では、保護範囲より編集対象の筆画を優先して消去する。
- 単語や資料に固有の規則は追加しない。
- 既存の crate の責務に沿って Rust で実装し、新しい OS 専用技術やモデルは導入しない。

## 実施手順

TDD で進める。
各段階で合成入力の回帰テストを先に追加し、Red を確認してから実装する。

### 1. 保護範囲の復元の修正 (原因 5)

1. 保護範囲が編集対象の見出しにかかる合成入力を作り、見出しの一部が背景に残ることをテストで確認する。
2. 編集対象の行の文字枠の内側では、その行の筆画マスクを保護範囲から除く。
   画面内の図形や UI の画素は、従来どおり元の画素を保持する。
3. 既存の記号保護と画面キャプチャのテストが変わらないことを確認する。

### 2. 罫線と枠線の検出 (原因 1)

1. `n2p-image` に、文字枠の外まで続く細い水平線と垂直線を壁として返す処理を追加する。
   OCR 領域の外で線分を検出し、同じ色の画素が続く範囲だけを OCR 領域の内側へ延長する方法を先に試す。
   既存の `rectangles.rs` の辺の検出を共有できるか確認する。
2. 背景との差は輝度だけでなく色差でも判定し、色付きの線も検出する。
3. 線の端の階調と暗い縁は、線の一部として残す。
4. テスト: 表の罫線と枠線を検出する。
   題字の長音記号のように文字枠の内側で閉じる筆画は検出しない。
   色付きの線を検出する。

### 3. 消去マスクの作り直し (原因 1、2)

1. 背景色を、筆画とその縁、壁を除いた広い範囲から推定する。
   密集した小さい文字では縁の画素が背景より多くなるため、文字枠の内側だけで推定しない。
2. 背景との差が大きい筆画を起点に、暗い縁と薄い影の画素へ最大 0.25 em まで広げる。
   壁の画素は加えない。
   起点から離れた淡い模様も加えない。
3. 文字色と字重の判定には、従来どおり `textmask::analyze_with_line_height` を使い、消去マスクだけを置き換える。
4. テスト: 暗い縁まで消去する。
   隣の罫線を含めない。
   離れた淡い格子線を含めない。

### 4. 補間方法の振り分けと背景色からの補間 (原因 2、4)

1. 全行のマスクを合成し、連結成分ごとに周囲の画素を調べる。
   壁を除く周囲のほぼすべてが背景色の許容差に収まる成分だけを、背景色からの補間に回す。
   それ以外の成分は LaMa に回す。
2. 背景色からの補間は、周囲の背景画素を境界値とするラプラス補間にする。
   境界値のない成分でも黒く崩れないよう、推定した背景色へ弱く引き寄せる項を加える。
   解法は共役勾配法から始め、1 ページの処理時間を測る。
3. LaMa が利用できない場合の処理は、背景色からの補間と従来の局所補間を実資料で比べて決める。
4. テスト: 単色のセルで罫線の画素が変わらず、セル内が背景色の許容差に収まる。
   グラデーションが連続する。
   壁に囲まれた成分が背景色になる。
   図形の縁に接する成分と、格子柄の上の成分が LaMa に回る。

### 5. 全行同時の LaMa (原因 3)

1. LaMa に回す成分を 1 枚のマスクに合成し、`Lama::inpaint_mask` をページごとに 1 回だけ呼ぶ。
2. 物体抽出が参照する消去済みマスクを、合成したマスクから作る。
3. `build.json` に、連結成分ごとの範囲、画素数、周囲の判定、補間方法、LaMa の呼び出し回数を記録する。
   壁は `mask-walls.png` として保存する。
   `macos-app/docs/conversion-quality-diagnostics.md` を更新する。
4. テスト: 1 ページで LaMa を 1 回だけ呼ぶ。
   モデルがある環境では、同じ形の行を繰り返す合成入力で、消去後に文字状の模様が現れないことを確かめる。
   モデルがない環境では、このテストを省略する。

### 6. 表の小さい文字の扱い (別判断)

段階 1〜5 の結果を実資料で確認してから、小さい文字の表を編集可能に戻すかを決める。
戻す場合は `small_ui_text` の判定を見直し、画面キャプチャの細字を画像に残す既存の方針と両立させる。
この判断はユーザーに確認する。

## 検証

- `macos-app/` で `cargo test --workspace`、`cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings` を実行する。
- `cargo run -p xtask -- compat` と `cargo run -p xtask -- visual-diff --dir fixtures/probe-pptx` を実行する。
  消去処理の変更は既存 fixture の OOXML に影響しない見込みで、差分が出た場合は原因を確認する。
- ローカルに保持している実資料 2 件の全ページを、同じ条件で変換する。
  条件は 150 DPI、Vision `ja-JP,en-US`、高解像度背景、`--erase lama`。
  対象は今回の資料と、P0〜P2 の確認に使った資料である。
- `macos-app/scripts/full_page_review.py` で修正前と修正後を比較し、ユーザーが目視で確認する。
  P0〜P2 で確認済みのページに回帰がないことも確認する。
- `xtask quality-eval` に領域別の評価を設定する。
  項目は罫線の保持、セル内の色ずれ、保護画素、マスクの重なりとする。
- `macos-app/scripts/conversion_benchmark.py` で、変換時間とピーク RSS を修正前と比べる。
  どちらかが 10% を超えて悪化した場合は、原因を調べてから進める。
- 公開する比較画像は合成入力で作り、実資料の画像と OCR の全文は公開しない。

## リスクと対応

| リスク | 対応 |
| --- | --- |
| 罫線を誤検出し、文字の一部が消え残る | 文字枠の外まで続くことを条件にする。消え残りの画素数を診断に出し、実資料で確認する |
| 罫線に密着した文字の一部が点として残る | 試作でも発生した。壁の太さと延長の条件を調整し、残る場合は既知の制約として記録する |
| 短い接続線や小さな装飾が消える | 長い線とつながる短い線の扱いを試す。対応できない場合は既知の制約とする |
| 暗い縁の拡張が隣の図形に入る | 周囲の判定で LaMa に回す。LaMa がない場合の影響は実資料で確認する |
| 大きな文字の跡に輪郭がうっすら残る | 実資料で LaMa の結果を確認し、目立つ場合は縁の拡張幅を見直す |
| 処理時間やメモリが増える | 壁の検出と補間の時間を測り、必要なら縮小画像での検出や解法の変更を検討する |
