## キャッシュと実行環境

1. 既存の LaMa 原本は読み取りのみとし、`N2P_LAMA_MODEL` で指定する専用ディレクトリへコピーする。
2. 「モデル変換キャッシュなし」は各試行に新しいディレクトリを作り、変換済み ONNX と `coreml/v1` がないことを検査する。
3. 「準備済み」は版ごとに専用ディレクトリを作り、計測外の変換を 1 回実行した後に使う。
4. OS のファイルキャッシュ、CoreML 内部の共有キャッシュ、Vision のシステム内キャッシュは削除しない。
   この条件を「完全な cold」と呼ばない。
5. macOS では `N2P_LAMA_DEVICE=gpu` を指定し、CPU と GPU を許す CoreML の経路を固定する。
   ログ、モデル変換とコンパイルの生成物、出力を確認し、LaMa の失敗や補間へのフォールバックを成功として採用しない。
6. 電源状態、OS、CPU とメモリ、App Nap に関する制御の有無、試行前後の競合プロセスを記録する。
   ビルドやテストと計測を同時に実行しない。
